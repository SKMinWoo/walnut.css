--wal-accent-hue: 31;   /* you write this  */
--wal-gold-hue:   78;   /* and this        */
--wal-olive-hue:  140;  /* and this        */

/* bloom  = accent + 27°   ← derived */
/* cool   = accent + 209°  ← derived */

            

              

                You set the accent, gold and olive. Bloom sits 27° past the accent and
                cool 29° past its opposite, so both turn with it and keep their distance.
              

              

                A palette can set either outright. Forest, Dusk and Bone choose their
                own cool; wear one and the arc shows its offset.

02

          
One declaration covers both modes

          
And any subtree that wants the other one

        


        

          

            
--wal-bg: light-dark(
  oklch(93% …),   /* light */
  oklch(16% …)    /* dark  */
);

            

              light-dark() resolves where a token is used, not
              where it is declared, so any subtree can take the other mode. Both panels
              run the same markup and tokens; only color-scheme differs.
            

            

              Because it is a real color-scheme, native form controls and
              scrollbars follow it too.

            shadow, label type and Catalogue's paper tooth. Palette answers what
            colour; finish answers what kind of object, and the two
            combine freely. The tokens are registered, so switching a finish tweens.

Papers on a walnut desk

          
One class, its grain drawn by the browser from the ground rod

        


        

          
<html class="wal-press wal-desk">

          

            

              The grain under this page is the ground rod a few points darker, drawn
              by the browser from noise, not shipped as a photo. Turn the ground hue
              and the wood follows, never dark enough to cost any text its contrast.
            

            

              Cards, plates and metrics rest a shadow above it. The finish sets how
              high: Catalogue lies almost flat, Soft lifts off.

Install

          
One link tag. No build step, no runtime.

        


        

          
<link rel="stylesheet"
  href="https://cdn.jsdelivr.net/gh/SKMinWoo/walnut.css@v0.4.0/dist/walnut.min.css">
<!-- optional: a named palette -->
<link rel="stylesheet"
  href="https://cdn.jsdelivr.net/gh/SKMinWoo/walnut.css@v0.4.0/dist/themes/press.css">

<html class="wal-press"
      data-finish="catalogue">

          

            jsDelivr serves the tagged release from GitHub, or copy
            dist/ into your project.
          

        


        

          The base stylesheet carries a complete colour script, so a palette file is
          optional, and unneeded if you write your own.

          Fills and type are different colours
          

            

              Goldenrod is a fine button and an illegible paragraph. Each cue therefore has
              four forms, and picking the right one is most of what good theming is.
            

            

              
TokenUse

              
                
--wal-goldThe cue as a fill
                    

                
--wal-gold-inkThe cue as type
                    goldenrod text

                
--wal-gold-softA 15% wash
                    soft

                
--wal-gold-fgLegible on the cue
                    on gold

              
            

          

        


        

          Chroma is an input because the sRGB gamut is not a circle
          

            

              The gamut is not the same width at every hue. At 62% lightness
              c = 0.17 is in gamut around terracotta and clips across much of
              the arc from green to blue, where the browser flattens it silently and the
              colour stops matching the hue you asked for. CSS cannot compute the gamut
              edge, so turning a hue far from its shipped value means lowering its chroma
              too. Push the accent chroma to the top of the rods above and sweep the hue
              to see where it stops tracking.
            

          

        


        

          Your CSS wins by default
          

            
@layer reset, tokens, base, layout, components, finish, utilities, cinema;

/* unlayered: beats all of the above */
.wal-card { border-radius: 3px; }

            

              Unlayered rules beat every layered one whatever their specificity, so an
              ordinary rule of yours overrides walnut with no !important. Two
              caveats: it wins only for the properties it declares
              (override flex-direction and walnut's gap still
              applies), and !important inverts layer order, so walnut's
              reduced-motion block still wins, on purpose.
            

          

        


        

          The one naming trap
          

            

              wal-text-* sets a font size.
              wal-color-* sets a colour. There is no
              .wal-text-muted class; it is a token name, and as a class it
              fails silently.
            

            
<p class="wal-text-sm wal-color-muted">small and muted</p>

<!-- does nothing: .wal-text-muted is not a class -->
<p class="wal-text-muted">still full size, full contrast</p>

          

        


        

          Browser support
          

            

              light-dark() sets the floor: Chrome / Edge 123, Safari 17.5,
              Firefox 120. Relative colour syntax, for the computed -fg tokens,
              sits behind @supports and falls back to a stated value.
            

            

              Above the floor, two things arrive later. .wal-retune and
              .wal-cue-in tween registered @property values,
              which Firefox has from 128; below that the page still switches, it
              just cuts. On this page, the dimension arcs on the colour wheel use
              mod() (Chrome / Edge 125) and are missing without it.
            

            

              The newest parts, such as superellipse corners and any-colour tints, add
              themselves where the browser has them. Openings
              gives each one's fallback.
