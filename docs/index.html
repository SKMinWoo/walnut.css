--wal-accent-hue: 31;   /* you write this  */
--wal-gold-hue:   78;   /* and this        */
--wal-olive-hue:  140;  /* and this        */

/* bloom  = accent + 27°   ← derived */
/* cool   = accent + 209°  ← derived */

            

              

                Bloom is a warm step after the lead. Cool lands 29° past the lead's
                direct opposite — a split complement, across the wheel from it but not
                dead against it. Both are defaults, so they turn with the accent and
                hold their distance. Gold and olive stay where you put them.
              

              

                A palette can still set either one outright. Forest, Dusk and Bone each
                choose their own cool — switch to one and the arc shows the offset it
                picked instead.

02

          
One declaration covers both modes

          
And any subtree that wants the other one

        


        

          

            
--wal-bg: light-dark(
  oklch(93% …),   /* light */
  oklch(16% …)    /* dark  */
);

            

              A custom property substitutes its var()s where it is
              declared, but a light-dark() inside it is just more tokens —
              so it resolves where the token is used, not where it is declared. Both panels here run the same markup and the same
              tokens — only color-scheme differs.
            

            

              Because it is a real color-scheme, native form controls and
              scrollbars follow it too.

Foregrounds are computed, not chosen

        

          

            

              
light · accent sits at L 0.52

              
Text on the accent

            

            

              
dark · accent sits at L 0.62

              
Text on the accent

            

          

          

            Those two blocks carry opposite foregrounds, and no rule names
            either one. The accent crosses the legibility threshold between modes, so
            --wal-accent-fg derives near-white on paper and near-black on a
            dark ground — from the cue's own lightness, every time you rotate it.

  --wal-radius: 3px;

  --wal-elevation: 0.35;
  --wal-wash: 0;
  --wal-line-boost: 1.7;
  --wal-tracking-label: 0.12em;

}

          

            A finish is a retune of the geometry and atmosphere tokens every component
            already reads — no component selectors, so adding a component never means
            updating a finish. Palette answers what colour; finish answers
            what kind of object. They compose freely. And because the tokens
            are registered numbers, switching a finish tweens them — press the button
            and watch the corners round off and the rules soften.

  href="https://cdn.jsdelivr.net/gh/SKMinWoo/walnut.css@v0.4.0/dist/walnut.min.css">

  href="https://cdn.jsdelivr.net/gh/SKMinWoo/walnut.css@v0.4.0/dist/themes/press.css">

            jsDelivr serves the tagged release straight from GitHub. Or copy
            dist/ into your project: it is plain CSS with no runtime.
          

        


        

          The base stylesheet already carries a complete script, so a palette file is
          optional — and unnecessary if you are writing your own.

          Fills and type are different colours
          

            

              Goldenrod is a fine button and an illegible paragraph. Each cue therefore has
              four forms, and picking the right one is most of what good theming is.
            

            

              
TokenUse

              
                
--wal-goldThe cue as a fill
                    

                
--wal-gold-inkThe cue as type
                    goldenrod text

                
--wal-gold-softA 15% wash
                    soft

                
--wal-gold-fgLegible on the cue
                    on gold

              
            

          

        


        

          Chroma is an input because the sRGB gamut is not a circle
          

            

              The gamut is not the same width at every hue. At 62% lightness
              c = 0.17 is in gamut around terracotta and clips across much of
              the green–blue arc, where the browser flattens it silently and the rendered
              colour stops matching the hue you asked for. CSS cannot compute the gamut
              boundary, so rotating a hue far from its shipped value means lowering its
              chroma with it. Push the accent chroma to maximum in the workbench and sweep
              the hue to see exactly where it stops tracking.
            

          

        


        

          Your CSS wins by default
          

            
@layer reset, tokens, base, layout, components, finish, utilities, cinema;

/* unlayered — beats all of the above */
.wal-card { border-radius: 3px; }

            

              Unlayered declarations beat every layered one regardless of specificity, so
              an ordinary rule of yours overrides the framework with no
              !important. Two caveats: an unlayered rule only outranks the
              framework for the properties it declares — override
              flex-direction and walnut's gap still applies — and
              !important inverts layer order, so walnut's reduced-motion block
              deliberately still wins.
            

          

        


        

          The one naming trap
          

            

              wal-text-* sets a font size.
              wal-color-* sets a colour. There is no
              .wal-text-muted class — that is a token name, and using it as a
              class fails silently.
            

            
<p class="wal-text-sm wal-color-muted">small and muted</p>

<!-- does nothing: .wal-text-muted is not a class -->
<p class="wal-text-muted">still full size, full contrast</p>

          

        


        

          Browser support
          

            

              light-dark() sets the floor: Chrome / Edge 123, Safari 17.5,
              Firefox 120. Relative colour syntax — the computed -fg tokens —
              sits behind @supports and degrades to a stated value.
            

            

              Above the floor, two things arrive later. .wal-retune and
              .wal-cue-in tween registered @property values,
              which Firefox has from 128; below that the page still switches, it
              just cuts. On this page, the dimension arcs on the colour wheel use
              mod() (Chrome / Edge 125) and are missing without it.
